## Array/Slice Fields: Publications and Genes

⚠️ **IMPORTANT**: Both `Publications` and `Genes` are **array fields** (`[]string` in Go) that support multiple values per plasmid.

### How Lookup Files Work

The publication and gene files are **lookup tables** where multiple rows with the same plasmid name are aggregated:

**Publication File Structure**:
```tsv
plasmid_name	publication_id
plasmid_name	publication_id
```
- Multiple publications per plasmid → multiple rows with same name
- Loader aggregates into `Publications []string` array
- GoldenBraid data: All 285 plasmids have single PMID → single-element arrays

**Gene File Structure**:
```tsv
plasmid_name	gene_id
plasmid_name	gene_id
plasmid_name	gene_id
```
- Multiple genes per plasmid → multiple rows with same name
- Loader aggregates into `Genes []string` array
- GoldenBraid data: ~40% have genes, some with multiple genes

**Example Aggregation**:
```tsv
# Input file (gene.tsv)
pDGB_O1N_0001	abpC
pDGB_O1N_0001	gtaC
pDGB_O1N_0001	H2Bv3
pUPD2_0003	abpC

# Results in plasmid struct:
# pDGB_O1N_0001.Genes = ["abpC", "gtaC", "H2Bv3"]
# pUPD2_0003.Genes = ["abpC"]
```

### GoldenBraid CSV Specifics

| Field | CSV Format | File Format | Result Array |
|-------|------------|-------------|--------------|
| Publications | Single PMID per row | One row per plasmid | `["32232356"]` for all plasmids |
| Genes | Comma-separated list | One row per gene | `[]` or `["gene1", "gene2", ...]` |

**Example Transformation**:
```csv
# CSV Input
pDGB_O1N_0001,...,"abpC, gtaC, H2Bv3",...

# Gene File Output (TSV)
pDGB_O1N_0001	abpC
pDGB_O1N_0001	gtaC
pDGB_O1N_0001	H2Bv3

# Final Plasmid.Genes Array
["abpC", "gtaC", "H2Bv3"]
```

## Important: Lookup Key Changes

⚠️ **CRITICAL**: Since ID is now auto-generated, the lookup files use **Name** as the key:

| File | Key Field | Value |
|------|-----------|-------|
| Annotator | Column 0 | Plasmid Name (e.g., "pDGB_A1") |
| Publication | Column 0 | Plasmid Name (e.g., "pDGB_A1") |
| Gene | Column 0 | Plasmid Name (e.g., "pDGB_A1") |

The loader must match records by **Name** field, not by ID (since ID doesn't exist yet).

## Data Transformation Requirements

### Simplified ETL Pipeline

1. **Parse CSV** → Extract columns 0, 3, 5, 6

2. **Generate Main Plasmid TSV**:
   - Extract: `Plasmid Name` (col 0), `Description` (col 5)
   - Format: Tab-separated, 2 columns
   - Output: 285 rows

3. **Generate Annotator CSV**:
   - For each plasmid: Name (col 0), CLI email, default timestamps
   - Format: CSV, 4 columns
   - Output: 285 rows

4. **Generate Publication TSV**:
   - Extract: `Plasmid Name` (col 0), `PMID` (col 6)
   - Format: Tab-separated, 2 columns
   - Output: 285 rows

5. **Generate Gene TSV**:
   - Parse comma-separated genes from col 3
   - Create one row per plasmid-gene pair
   - Format: Tab-separated, 2 columns
   - Output: ~120-150 rows

## Recommended Implementation Approach

### Direct CSV Parser (Recommended)

Create a dedicated GoldenBraid CSV parser that:
- Reads Goldenbraid_final.csv
- Generates all 4 required input files
- Handles gene list splitting (comma-separated → individual rows)
- Accepts user email as parameter
- Applies default timestamps
- Uses fp-go for type-safe transformations

**Advantages**:
- Single transformation step
- Type-safe with fp-go monads
- Easier to test and validate
- Reusable for future loads
